# AWS SCS-C03 一問一答

AWS Certified Security – Specialty（**SCS-C03**）の学習用の静的サイト。
GitHub Pages にそのまま置けます。ログインもサーバーもなく、解答履歴はブラウザの localStorage にだけ保存されます。

https://nakiusa.github.io/aws-scs/

## 収録内容

- **一問一答 233問** — サービスの役割、紛らわしいサービスの対比、既定値と制約。4択と暗記カードを切り替えられます
- **シナリオ問題 122問** — 本試験と同じ形式。誤答それぞれについて「なぜ違うのか」を表示します

どの問題にも、解説とは別に**思想**の欄が付いています。
そこに書いてあるのは正解の理由ではなく、AWS がなぜそういう設計をしているのか、
そして同じ形の設問が出たときにどう読めば選択肢を絞れるか、という判断の型です。

## SCS-C03 の試験情報

2025年12月2日から SCS-C02 に代わって実施されている版です。

| 項目 | 内容 |
|---|---|
| 問題数 | 65問（うち15問は採点対象外） |
| 時間 | 170分 |
| 合格ライン | 1000点満点中 750点 |
| 出題形式 | 択一、複数選択、**並べ替え**、**組み合わせ** |

| 分野 | 比率 |
|---|---|
| 第1分野: 検出 | 16% |
| 第2分野: インシデント対応 | 14% |
| 第3分野: インフラストラクチャのセキュリティ | 18% |
| 第4分野: アイデンティティとアクセスの管理 | 20% |
| 第5分野: データ保護 | 18% |
| 第6分野: セキュリティの基礎とガバナンス | 14% |

## C02 から何が変わったか

**分野の切り分けが変わりました。**
C02 の「脅威検出とインシデント対応」と「セキュリティのログ記録とモニタリング」が解体され、
検知に関わるものが第1分野（検出）に、対応に関わるものが第2分野（インシデント対応）に集まりました。
第6分野は「管理とセキュリティガバナンス」から「セキュリティの基礎とガバナンス」に改称されています。

**IAM が最大の分野になりました。** 16% から 20% へ上がり、単独で最も重い分野になっています。
逆にインフラストラクチャのセキュリティは 20% から 18% に下がりました。

**出題形式が増えました。** 択一と複数選択に加えて、手順を正しい順に並べる問題と、
項目どうしを対応づける問題が入ります。このサイトでもこの3形式を用意してあります。

**追加された論点**（公式ガイドの新旧比較に挙がっているもの）:

- 生成 AI アプリケーションの保護（Bedrock のガードレール、OWASP の LLM 向けトップ10）
- 検出結果の妥当性確認と影響範囲の評価
- OCSF 形式でのデータ取り込み、第三者の WAF ルールとの統合
- リソース間の転送中暗号化（EMR、EKS、SageMaker AI のノード間、Nitro）
- インポートしたキーマテリアルと AWS 生成キーマテリアルの違い
- 機密データのマスキング（CloudWatch Logs のデータ保護ポリシー、SNS のメッセージデータ保護）
- 単一および複数リージョンでの鍵と証明書の管理（AWS Private CA）

**削除された論点**: ASFF の詳細、AWS セキュリティインシデント対応ガイド、CloudTrail のログ形式の細部、
ホストベースのセキュリティ、TCP/IP の基礎、ポリシーの構成要素（Principal / Action / Resource / Condition）、
TLS の概念、S3 の静的ウェブサイトホスティング、アーキテクチャレビューとコスト分析によるギャップの特定。

**新しく在庫に入った主なサービス**: AWS Fault Injection Service、AWS Resilience Hub、
Automated Forensics Orchestrator for Amazon EC2、Amazon Application Recovery Controller、
Amazon Verified Permissions、Network Access Analyzer、EC2 Image Builder、Amazon CodeGuru Security、
Amazon Q Developer、Amazon Bedrock、Amazon Managed Grafana、AWS DataSync、AWS Client VPN、
AWS Well-Architected Tool、AWS User Notifications。
Organizations には宣言型ポリシーとメンバーアカウントのルートアクセスの一元管理が加わっています。

> 分野の対応づけは公式ガイドの付録でも多対多になっています（C02 の1つのタスクが C03 の3〜4のタスクに分かれる）。
> このサイトでは、各問題の主題にあたる分野を1つ選んでタグ付けしています。

## 使い方

1. **一問一答**タブで、カテゴリを絞って回す。既定は**4択**で、`1`〜`4` キーで解答、`Space` で次の問題へ進む
2. 習熟度は問題ごとに0〜3で記録され、「未習得のみ」で回し直すと苦手な問題だけが出てくる
3. **シナリオ問題**タブで、要件から構成を選ぶ練習をする。65問モードで本番と同じ分量を通す
4. **進捗**タブでカテゴリ別の習熟度と正答率を見る

一問一答には**暗記カード**モードもあります。選択肢を出さずに解答を開き、「わかった / あやふや」で自己採点する形式です。4択は消去法で当たってしまうので、仕上げの確認にはこちらを使ってください。

### 出題形式ごとの操作

| 形式 | 操作 |
|---|---|
| 択一 | 選択肢をクリック、または `1`〜`4` キー |
| 複数選択 | 数字キーかクリックで入り切りし、「解答する」を押す |
| 並べ替え | 正しいと思う順にクリックすると番号が付く。「選び直す」で解除 |
| 組み合わせ | 各行のプルダウンで選び、「解答する」を押す |

複数選択、並べ替え、組み合わせは、**すべて正しくないと正解になりません**（本試験と同じ）。

### 4択の選択肢について

一問一答の誤選択肢は、**同じカテゴリの他の問題の解答**をそのまま流用しています（文章を生成していないので、誤選択肢のはずが実は正しい、という事故が起きにくい）。解答が実質同じになる問題どうしは、サービス名の重なりを見て除外しています。

シナリオ問題の選択肢は一問ずつ書き下ろしたもので、誤答には個別の理由が付いています。

### 合格の目安

- カテゴリ別の習熟が、どのカテゴリも8割以上
- シナリオ問題の正答率が、初見の問題でも安定して8割以上

### 問題を解くときのコツ

選択肢は「技術的に動くかどうか」ではなく「設問の要件に最も合うか」で選びます。
設問には必ず優先順位を示す語が入っているので、そこを先に読むと候補が絞れます。

- 「管理者にも削除させない」「例外を認めない」→ 権限（IAM、バケットポリシー、SCP）では答えられない。Object Lock、Glacier ボールトロック、バックアップボールトロックのように、権限の外側にある仕組みを選ぶ
- 「メンバーアカウントの管理者が解除できないこと」→ 組織レベルの仕組み（SCP、RCP、宣言型ポリシー、組織証跡）
- 「防ぎたい」「させたくない」→ 予防（SCP、条件付き Deny、Service Catalog、CloudFormation Hooks）。検出で答える選択肢は落ちる
- 「気づきたい」「把握したい」→ 検出（Config、GuardDuty、Access Analyzer、Network Access Analyzer）
- 「今後もアカウントが増える」「運用負荷を最小に」→ 列挙や手作業を含む選択肢は落ちる
- 「ほぼリアルタイム」→ バッチ処理（エクスポート、定期クエリ）は落ちる
- 「変更を加える前に」→ Policy Simulator。「現在の状態を洗い出したい」→ Access Analyzer
- 「起こりうる経路を知りたい」→ 到達可能性の分析。ログは「起きたこと」しか答えない

## ローカルで動かす

```bash
python3 -m http.server 8000
```

`http://localhost:8000` を開いてください。ビルドは不要です。

## 問題を追加・修正する

`data/*.js` が問題の実体です。各ファイルは配列に push するだけの形なので、追記すればそのまま反映されます。

```js
// 一問一答
{ id: "一意のID", cat: "カテゴリ名", d: 1,
  q: "問題文", a: "解答",
  note: "解説（事実として何が正しいか）",
  idea: "思想（なぜ AWS はそう設計したのか、どう読めば選べるか）" }

// シナリオ問題（択一）
{ id: "...", cat: "...", d: 1,
  q: "状況設定の問題文",
  c: ["選択肢A", "選択肢B", "選択肢C", "選択肢D"],
  ans: 0,                                  // 正解のインデックス
  exp: "正解の理由",
  ng: ["", "Bが違う理由", "Cが違う理由", "Dが違う理由"],
  idea: "思想" }

// 複数選択（選択肢は5つ以上、正解は2つ以上）
{ ..., type: "multi", c: [...], ans: [0, 3], ng: [...], idea: "..." }

// 並べ替え（選択肢は3〜5個。ans は c のインデックスを正しい順に並べる）
{ ..., type: "order", c: [...], ans: [2, 0, 1, 3], idea: "..." }

// 組み合わせ（3〜7組。右側の値は重複させない）
{ ..., type: "match", pairs: [["プロンプト", "対応する答え"], ...], idea: "..." }
```

`d` は試験分野（1〜6、上の表の順）。
`cat` は既存のカテゴリ名を使うと絞り込みに混ざります。新しい名前を書けば新しいカテゴリになります。
問題文と解説の中では `` `バッククォート` `` で囲むとコード表記になります。
`ng` は択一と複数選択で使えます（正解の位置は空文字）。並べ替えと組み合わせでは使いません。

`index.html` に `<script>` の行を足せば、ファイルを分けて追加することもできます。

## 注意

出題内容は SCS-C03 の公式試験ガイドに沿って作成していますが、AWS のサービス仕様は変わります。
仕様の細部や上限値については、迷った時点で公式ドキュメントを確認してください。
また、この教材は AWS 公式のものではなく、実際の試験問題とは関係ありません。

公式の試験ガイド: https://docs.aws.amazon.com/aws-certification/latest/security-specialty-03/security-specialty-03.html

## データの引き継ぎ

解答履歴はこの端末のブラウザにだけ保存されます。別の端末へ移すときは、進捗タブから JSON を書き出して読み込んでください。ブラウザのデータを消すと履歴も消えます。

なお、保存キーは C02 版（`awsscs.c02.v1`）から `awsscs.c03.v1` に変わっています。分野の構成が変わり問題も入れ替わったため、C02 版の履歴は引き継がれません。
